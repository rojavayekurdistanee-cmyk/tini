# نقاط عرش Tini الآمنة — اعتماد على أحدث main

نقطة البداية: `71c594b330e1eea7f23bd4108c833eade072cbad` من GitHub. أُعيد بناء كائن Git وشجرته من النسخة الفعلية والتحقق من SHA، وليس من نسخة العمل السابقة. الفرع المستقل: `codex/tini-throne-secure-points`. لم يُعدّل main.

## ما تغيّر

أصبحت نقاط العرش مستقلة في `throne_wallets/{uid}`، بحقول `schemaVersion: 1` و`availablePoints` و`reservedPoints`. جميع الكتابات من السيرفر فقط، والقراءة لصاحب الحساب فقط. يبدأ السجل بصفر عند المزامنة؛ لا تُنسخ إليه قيم `titiBalance` أو `tiniBalance` أو أي حقول مالية من ملف المستخدم.

أصبح العرش `schemaVersion: 3` وإعداد تفعيله `financialSafetyVersion: 3`. كل عمليات الحجز والاسترداد وتسوية الفوز تستخدم السجل الجديد داخل معاملات Firestore. الاستحقاقات وعدد التتويجات تبقى في `throne_entitlements`. لا يكتب محرك العرش الجديد أي رصيد أو عدد تتويجات داخل `users`.

يمكن تعديل حقول الرصيد القديمة وفق قواعدها الحالية دون أن يُنتج ذلك نقطة عرش واحدة. لا تغيير على ملفات الصناديق أو المحفظة أو مدخل وظائف Firebase الأصلي أو اعتمادياتها. قراءة النقاط في `CrownProvider` مرتبطة بالسجل الجديد، بينما الاسم ورقم التاج يظلان من ملف المستخدم. تمنع القواعد حذف ملف المستخدم أثناء وجود حجز عرش نشط، وكذلك كتابة/حذف/إنشاء سجل نقاط من العميل.

هذه نقاط عرش منفصلة. لا توجد حاليًا واجهة شراء أو تحويل أو مكافأة تمنحها؛ منح نقاط الاختبار إجراء إداري موثّق فقط. لا تمنح callable عامة أي نقاط، ولا تمنح المزامنة نقاطًا مجانية.

## الأدوات الإدارية

`functions/throne-v2/admin.js` أداة طرفية وليست Cloud Function مصدّرة. تتطلب صلاحية Google/Firebase إدارية صالحة، ولا تحتوي على مفتاح أو كلمة مرور. كل أمر يطلب اسم المشروع صراحةً ويطابقه مع `.firebaserc`؛ المشروع الحالي هو `titi-star0`.

```sh
# عرض الحالة فقط، دون تعديل بيانات
node functions/throne-v2/admin.js status --project=titi-star0

# منح 20,000 نقطة اختبار لحساب موجود بعد تسجيل دخوله وإنشاء ملفه في التطبيق
node functions/throne-v2/admin.js grant --project=titi-star0 --uid=YOUR_ACCOUNT_UID --points=20000 --operation-id=first-throne-test-20261110

# نفّذ لحساب الاختبار الثاني باستخدام UID الخاص به ومعرّف عملية واضح
node functions/throne-v2/admin.js grant --project=titi-star0 --uid=SECOND_ACCOUNT_UID --points=20000 --operation-id=second-throne-test-20261110

# تفعيل الإصدار الجديد بعد نشر الوظائف والقواعد والفهرس وتحديث التطبيق
node functions/throne-v2/admin.js activate --project=titi-star0

# إيقاف العروض الجديدة مع استمرار إنهاء الفترات القائمة بأمان
node functions/throne-v2/admin.js pause --project=titi-star0
```

إعادة أمر منح النقاط بنفس UID ومعرّف العملية والمبلغ لا تضاعف النقاط. تغيير المبلغ مع إعادة معرّف العملية يُرفض. يسجّل كل منح في `throne_ledger` بنوع `admin_grant`. لا تستخدم هذه الأداة لتغيير رصيد محفظة آخر.

يُنشئ `activate` مزاد v3 عند غياب الحالة، أو يحدّث **مزاد v2 الفارغ فقط**: أعلى عرض صفر، دون متصدر أو ملك، وغير مقفل. لا يعيد ضبط حكم أو عرض قديم، ولا ينسخ/يسترد نقاطًا قديمة. يرفض أي حالة قديمة غير فارغة دون تغييرها. إعادة التفعيل مع وجود v3 لا تنشئ مزادًا ثانيًا.

## ترتيب التنفيذ على مشروع Firebase الحالي

لا يلزم إنشاء مشروع Firebase سحابي تجريبي منفصل، لأن التطبيق لم يُطلق والمستخدم أوضح أنه لا يملك نقاطًا أو أرصدة حاليًا. مع ذلك تُفحص الحالة الموجودة فعليًا قبل أي تفعيل؛ لا يُفترض أن قاعدة البيانات فارغة.

1. حدّث ملفات هذا الفرع في نسخة التطبيق، خصوصًا `lib/crown_provider.dart`. العميل القديم لا يقرأ سجل النقاط الجديد، وسيظل غير متوافق مع حالة v3.
2. جهّز Firebase CLI للنشر، وصلاحية Google Application Default Credentials أو حساب خدمة للأوامر الإدارية. تسجيل الدخول إلى Firebase CLI وحده قد لا يجهز اعتماديات Admin SDK. لا تضع أي مفتاح في GitHub أو الدردشة.
3. اقرأ الحالة باستخدام أمر `status` أعلاه، وتحقق من مشروع `titi-star0`. لا تغيّر حالة قديمة غير فارغة تلقائيًا.
4. انشر حزمة العرش والقواعد من هذا المصدر، دون نشر حزمة الوظائف الأصلية:
   ```sh
   firebase deploy --project=titi-star0 --only=functions:throne-v2,firestore:rules
   ```
5. أنشئ الفهرس الوارد في `firestore.throne.indexes.json` إضافةً إلى الفهارس الحالية: مجموعة `throne_reigns`، الحقل `completed ASC` ثم `crownedAt DESC`. انتظر حالة Ready. لا تنشر قائمة جزئية إذا كان ذلك سيحذف فهارس أخرى.
6. تحقق من إعداد App Check للحساب/الجهاز الذي سيُختبر؛ callable تفرض App Check. لا تعطل الحماية لتجاوز خطأ إعداد.
7. سجّل الدخول من التطبيق بحسابك وبحساب اختبار ثانٍ؛ انسخ UID لكل حساب من Firebase Authentication، ثم امنح نقاط اختبار بأوامر إدارية محددة.
8. نفّذ `activate` ثم افتح نسخة التطبيق الجديدة وأعد المزامنة. اختبر عرضًا عاديًا، زيادة المتصدر، الاسترداد، فوز 10,000، وإغلاق المزايدات. لا تغيّر الساعة أو تواريخ الحكم على المشروع الحقيقي لتسريع الاختبار؛ الحالات الزمنية المغطاة بالمحاكي لا تتطلب انتظار أسبوع.
9. راجع `throne_wallets` و`throne_ledger` للتأكد من الرصيد المتاح والحجز والتسوية، ومنع تكرار الطلب والمنح والتفاعل. اختبر حسابين عبر جهازين أو جلستين مستقلتين.

## حالة النشر في هذه الجلسة

لم يُنفَّذ نشر أو منح نقاط أو تفعيل أو تغيير بيانات على `titi-star0`:

- محاولة `firebase projects:list` فشلت برسالة `Failed to authenticate, have you run firebase login?`.
- محاولة بدء تسجيل الدخول فشلت في الاتصال بـ`https://auth.firebase.tools/attest`؛ فحص الشبكة أعاد رفض CONNECT برمز 403 من سياسة البيئة.
- البيئة لا تعرض حساب خدمة أو هوية Google جاهزة. لا يجوز ادعاء النشر أو نجاح الاختبار على المشروع الحقيقي دون الوصول والتحقق الفعلي.

يلزم تمكين وصول البيئة إلى خدمات Firebase/Google وربط صلاحية النشر المناسبة، أو تنفيذ أوامر النشر من جهاز المطور المصرح له. لا حاجة لإرسال رموز أو كلمات مرور في الدردشة.

## الرجوع

نفّذ `pause` أولًا. احتفظ بسجلات النقاط والإيصالات والتاريخ، ودع المعاملات تكمل الفترات القائمة. لا ترجع السيرفر إلى مصدر النقاط القديم مع وجود حجوزات v3، ولا تحذف سجلات `throne_wallets` أو السجل المالي. إصلاح السيرفر مع إبقاء البيانات أو واجهة قراءة متوافقة أكثر أمانًا من إعادة الخصم المحلي. لا يوجد سكربت يرجع أو يغيّر أرصدة أخرى.

## قائمة الملفات

الملفات المعدّلة، وجميعها داخل `/workspace/tini/`:

- `firestore.rules`: حماية سجل نقاط العرش ومنع حذف ملف حساب لديه حجز نشط.
- `functions/throne-v2/throne.js`: نقل المعاملات والمزامنة والتتويج إلى سجل النقاط المحمي وإصدار الحالة الثالث.
- `lib/crown_provider.dart`: الاشتراك في سجل نقاط العرش والرصيد المحجوز والتوافق مع حالة v3.

الملفات الجديدة:

- `functions/throne-v2/admin.js`: عرض الحالة والتفعيل والإيقاف ومنح نقاط اختبار بإيصال يمنع التكرار؛ لا تُصدّر كـcallable.
- `functions/test/throne-wallet.test.js`: اختبارات المحاكي الـ26 للمعاملات والقواعد والنقاط والتفعيل.
- `test/throne_ui_test.dart`: اختبارات Flutter الـ12.
- `docs/throne-secure-points.md`: شرح التغيير وترتيب النشر وحدود التحقق.

لم يُحذف أو يُنقل أي ملف أصلي. لم تتغير الاعتماديات أو صور الشارات أو ملفات الصناديق أو المحفظة أو `functions/index.js` أو إعداد مشروع Firebase.
